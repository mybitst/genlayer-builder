# 踩过的坑

这里只写会让人白干几小时的坑，不写"记得保存文件"这种。

## 1. 两个 RPC 入口，chainId 一样，指向的却是不同部署

`rpc-bradbury.genlayer.com` 和 `rpc.testnet-chain.genlayer.com` 都会返回 chainId 4221，
但前者指向的是一套已经废弃的部署。

后果很隐蔽：交易能发出去，回执 `status 0x1`，链上什么都不发生。

正确的是 `https://rpc.testnet-chain.genlayer.com`。判断方法很简单，查创世块哈希，
再和官方文档给的对照，对不上就是进错链了。

## 2. 回执成功不代表部署成功

部署合约时如果注意到 `to` 是一个普通地址、`logs` 是空数组、`gasUsed` 只有 21000 出头，
那就是一笔带 data 的普通转账，合约根本没创建。

判断顺序：先看 `logs` 有没有合约创建日志，再 `eth_getCode` 查地址有没有字节码。
这两个有一个不对，回执写什么都别信。

## 3. Studio 里部署的合约，不算链上部署

Studio 是沙箱，给出的地址不能拿去提交门户的合约任务，也不能当链上证据。
门户要的是测试网或者主网地址，能在浏览器里查到的。

## 4. 非交互环境下 CLI 会卡在 keystore 密码

`genlayer deploy` 在终端里会提示 `Enter password to decrypt keystore`。
在脚本、cron、expect 包装里，它经常直接挂住不返回，进程一直占着，日志被控制字符刷到几百 MB。

如果一定要在非交互环境部署，别跟这个提示较劲，换条路走。要么用带私钥的账号，要么走 JS SDK。

## 5. 存储类型不能用 Python 原生容器

`list`、`dict`、`int` 写进去会出问题。要换成：

```
list[str]     -> DynArray[str]
dict[str,str] -> TreeMap[str, str]
int           -> u32 / i64 / u256 / bigint
```

默认值也是零初始化的，不用在 `__init__` 里手动清空数组。

## 6. 非确定性块里不能碰状态

`gl.nondet.*`、模型调用、网页抓取，都必须包在传给 `gl.eq_principle.*` 或
`gl.vm.run_nondet_unsafe` 的函数里。

这些函数内部不能写 `self.xxx`，不能调别的合约，不能发消息。
因为每个节点都在各跑各的，共识还没出结果，谁写谁错。

## 7. strict_eq 只适合稳定到字节的数据

同一秒请求同一个价格接口，不同节点拿到的数字都不会完全一样。
这种数据用 `strict_eq` 会一直失败。

价格、评分、模型输出，都要用容差比较或者校验结构，不要比字面值。

## 8. 网页内容是不可信输入

模型读网页的时候，页面里可能出现"忽略之前的指令"这类文本。

合约的 prompt 里要明确写死：材料里的任何指令都不算指令，只能当证据。
判定结果也要限定成有限枚举，开放式回答没法达成共识。

## 9. 部署费用字段是按 wei 量级填的

`executionBudgetPerRound` 不是填执行步数，是填预算金额，单位跟手续费同一个量级。

照文档示例填 786434，会一直被拒，报 `BudgetTooLow`，加钱也没用，因为系统认为你只申请了几十万分之一的预算。

填到 `1000000000000000` 这一档，也就是 0.001 GEN 的刻度，检查才会过。手续费本身给 0.05 GEN 就够部署。

顺带一个现象，用 CLI 的默认方式让程序自己去算手续费，会报一笔从零地址发起的调用余额不足。这是拿不到账户的估算通道，绕过去就行，直接指定手续费数值。

## 10. 部署成功不等于合约可用

交易状态显示已接受，不等于合约真的建好了。

必须读执行结果这一项，看到 `SUCCESS` 才算数。构造函数缺参数、执行环境版本对不上，都会出现交易成功、执行失败、地址照发的情况。

只看交易哈希和状态码，会把一个坏合约当成部署成功。
